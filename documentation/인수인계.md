최종 업데이트: 2026-10-07 (설교 페이지 유튜브 자동 연동, 헤더 lint 정리)

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 교회명 | 시선교회 (대한예수교 장로회) |
| 영문명 | SEE SUN CHURCH |
| 목적 | 시광교회(seetheglory.or.kr)와 유사한 형태의 교회 소개 사이트 |

| 프로덕션 URL | https://www.seesunchurch.or.kr (커스텀 도메인, Vercel 프로젝트 `seesun-church`에 연결됨) |

콘텐츠 원본은 `docs/`(기획 PPT/TXT)와 `src/lib/content.ts`(사이트에 반영된 공통 데이터)입니다. 페이지별 긴 본문은 각 `src/app/*/page.tsx`에 있습니다. **공지사항만은 예외**로, DB(Neon Postgres)에 저장되며 `/admin`에서 관리합니다 — 자세한 내용은 8장 참고.

## 2. 기술 스택

- **Framework**: Next.js 16 (App Router, `proxy.ts` — 구 middleware)
- **UI**: React 19, Tailwind CSS v4, Pretendard
- **아이콘**: `@phosphor-icons/react`
- **모션**: `motion`
- **DB**: Neon Postgres (Vercel Marketplace 연동), 드라이버 `@neondatabase/serverless`
- **파일 저장**: Vercel Blob (`@vercel/blob`) — 공지사항 첨부파일. 공개 URL로 저장되며 메타데이터는 `notices.attachments` JSONB에 둠
- **인증**: 공지사항 관리자(`/admin`) 전용 단일 계정 로그인. 회원가입/DB 유저 테이블 없음 — env 변수 두 개(`ADMIN_USERNAME`, `ADMIN_PASSWORD`)와 HMAC 서명 세션 쿠키로 동작
- **설교 영상**: YouTube Data API v3 (`YOUTUBE_API_KEY`) — 채널 @seesunchurch 업로드 목록을 1시간 캐시로 조회
- **호스팅**: Vercel (Node.js 24.x, Fluid Compute)
- **결제**: 없음

## 3. 로컬 실행

```bash
npm install
vercel link              # 최초 1회, .vercel/ 연결
vercel env pull .env.local --yes   # DB·관리자 로그인·Blob env 변수 받기 (필수 — 없으면 /admin, /notices 빌드는 되지만 DB/첨부 업로드 실패)
npm run dev      # http://localhost:3000
npm run build    # 프로덕션 빌드 검증
npm run lint     # ESLint (현재 에러 0건 — 배포 전 확인)
npm run start    # 빌드 결과 로컬 실행
```

Vercel CLI:

```bash
vercel whoami
vercel link          # .vercel/ 에 연결됨
vercel --prod        # 프로덕션 배포 (완료 후 자동으로 www.seesunchurch.or.kr 별칭됨)
```

> 로컬 개발 서버를 여러 번 재시작할 때, `vercel env pull` 이후에도 **이전에 띄워둔 `next dev` 프로세스가 새 env 변수를 못 읽는 경우**가 있습니다. `lsof -ti:3000`으로 기존 프로세스를 죽이고 다시 `npm run dev`를 실행하세요.

### 설교 (유튜브 자동 갱신)

`src/lib/youtube.ts`가 YouTube Data API(`playlistItems`, 채널 업로드 재생목록 최근 200개)로 영상을 가져와 **1시간마다** 갱신합니다. `구분 | 시리즈 | 제목 | 설교자 | 시선교회 (YYYY.M.D.)` 형식을 파싱합니다. 분류 규칙:
  - 제목이 `주일오전예배` / `금요기도회`로 시작 → 그 구분
  - 접두어가 없어도 **목사** 설교이고 설교일이 일요일이거나 제목에 「주일」 → 주일오전예배 (2026년 6월 이전 영상 형식)
  - `오후` / `가정예배` / `개척`이 들어간 제목, 접두어 없는 전도사 설교(주일 오후예배)는 제외

- 키가 없거나 API가 실패하면 `src/lib/content.ts`의 `sermons` 정적 목록으로 대체 표시 (Vercel 로그에 `[youtube]` 에러)
- 즉시 반영이 필요하면 재배포
- 파서 점검: `npx tsx scripts/check-sermon-title.ts`

## 8. 공지사항 관리 시스템 (`/admin`)

### 8.1 로그인

- URL: `https://www.seesunchurch.or.kr/admin/login`
- 계정은 **1개**, 아이디 `admin` (비밀번호는 Vercel env 변수 `ADMIN_PASSWORD`에 저장 — 이 문서에는 기록하지 않음)
- 로그인하면 `admin_session` 쿠키(HttpOnly, 7일 유효)가 발급되고 `/admin/*` 전체에 접근 가능
- 로그아웃은 관리자 목록 화면 우측 상단 버튼

### 8.2 비밀번호/계정 변경

```bash
vercel env rm ADMIN_PASSWORD production preview development --yes
vercel env add ADMIN_PASSWORD production --value "새비밀번호" --yes
vercel env add ADMIN_PASSWORD preview --value "새비밀번호" --yes
vercel env add ADMIN_PASSWORD development --value "새비밀번호" --yes
vercel env pull .env.local --yes   # 로컬 반영
vercel --prod                       # 프로덕션 재배포 (env 변경은 재배포해야 반영)
```

`ADMIN_USERNAME`도 동일한 방식으로 변경 가능합니다.

### 8.3 데이터 구조 (Neon Postgres `notices` 테이블)

| 컬럼 | 타입 | 설명 |
|------|------|------|
| `id` | SERIAL PK | |
| `title` | TEXT | 제목 |
| `summary` | TEXT | 본문 (긴 텍스트, 줄바꿈 유지) |
| `author` | TEXT | 글쓴이 (기본값 "관리자") |
| `views` | INTEGER | 조회수 (상세 페이지 열람 시 자동 +1) |
| `created_at` | TIMESTAMPTZ | 등록 일시 (자동, 수정 불가 — 목록/상세의 "등록일"은 이 값을 KST로 포맷) |
| `attachments` | JSONB | 첨부 메타데이터 배열. 기본값 `[]`. 파일 본체는 Vercel Blob에 두고 여기에는 `{ url, name, size }`만 저장 |

스키마는 `src/lib/db.ts`의 `ensureSchema()`가 매 요청 시(인스턴스당 1회) `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ... ADD/DROP COLUMN IF EXISTS`로 자동 보장합니다. 별도 마이그레이션 툴(Drizzle 등) 없음 — 컬럼을 추가/변경하려면 `db.ts`의 `ensureSchema()`에 `ALTER TABLE` 문을 추가하세요.

### 8.4 첨부파일

- 글쓰기(`/admin/new`)·수정(`/admin/[id]/edit`)에서 파일을 고르면 서버 액션이 Vercel Blob에 `notices/{원본파일명}`로 올린다 (`addRandomSuffix: true`, `access: "public"`).
- 제한은 `src/lib/attachments.ts`: **파일당 10MB, 한 글에 최대 5개**. 서버 액션 본문 한도는 `next.config.ts`의 `experimental.serverActions.bodySizeLimit = "12mb"` (multipart 오버헤드 여유).
- 공개 상세(`/notices/[id]`)에서 파일명·용량과 함께 다운로드 링크가 보인다. 목록(`/notices`)은 첨부가 있으면 제목 옆에 클립 아이콘을 붙인다.
- 수정 화면에서 기존 파일 옆 `삭제`를 체크하면 저장 시 Blob과 JSONB에서 함께 빠진다. 공지 자체를 삭제하면 그 글의 Blob도 같이 지운다.
- 업로드/삭제는 `src/app/admin/actions.ts`의 `put` / `del` (`@vercel/blob`). 토큰은 `BLOB_READ_WRITE_TOKEN`.
- 폼 UI: `src/components/NoticeForm.tsx`, `src/components/AttachmentField.tsx`.

### 8.5 DB 직접 확인

```bash
vercel env pull .env.local --yes
# .env.local의 DATABASE_URL로 psql 또는 Neon 콘솔(https://console.neon.tech) 접속
psql "$DATABASE_URL" -c "select id, title, author, views, created_at, attachments from notices order by created_at desc;"
```

Blob 목록 확인은 Vercel 대시보드 Storage → Blob, 또는 `@vercel/blob`의 `list()`로 한다. 경로 prefix는 `notices/`.

### 8.6 보안 메모

- 관리자 라우트 보호는 `src/proxy.ts`(Next 16 방식 — 구 `middleware.ts`)에서 세션 쿠키를 검사하며, 각 서버 액션(`src/app/admin/actions.ts`)에서도 `requireAdminSession()`으로 이중 검증합니다.
- 세션 토큰은 비밀번호 자체가 아니라 `SESSION_SECRET`으로 만든 HMAC 값입니다. `SESSION_SECRET`을 바꾸면 기존 로그인 세션이 전부 무효화됩니다.
- 비밀번호는 상수시간 비교(`crypto.timingSafeEqual`)로 검증합니다.
- 첨부파일 Blob은 `access: "public"`이라 URL을 아는 사람은 받을 수 있습니다. 민감한 문서는 올리지 않는 것이 원칙입니다.

## 11. 배포·운영 메모

1. `main` 푸시 후 Vercel 연동 배포가 동작할 수 있으나, CLI로 `vercel --prod` 하는 경우가 많습니다.
2. `vercel --prod`는 배포 후 자동으로 `www.seesunchurch.or.kr`에 별칭됩니다(출력의 `Aliased` 줄로 확인). 과거에는 `seesun-church.vercel.app`을 수동 별칭해야 했지만, 커스텀 도메인 연결 이후에는 자동으로 처리됩니다.
3. **SSO 배포 보호는 꺼 둔 상태**입니다. 다시 켜면 비로그인 사용자 접근이 막힙니다 (공지사항 관리자 로그인과는 별개 — 그건 SSO가 아니라 사이트 자체 로그인입니다).
   - 확인: `vercel project protection seesun-church`
   - 끄기: `vercel project protection disable seesun-church --sso`
4. `.env.local`, `.vercel/` 은 gitignore. **`.env.local`에 시크릿이 들어 있습니다** — `DATABASE_URL`(Neon), `ADMIN_USERNAME`/`ADMIN_PASSWORD`/`SESSION_SECRET`(관리자 로그인), `BLOB_READ_WRITE_TOKEN`(첨부 업로드), `YOUTUBE_API_KEY`(설교 목록). git에 커밋되지 않도록 주의.
5. Vercel CLI가 오래됐다면: `npm i -g vercel@latest` 권장.
6. **YouTube API 키**는 Google Cloud Console에서 발급(YouTube Data API v3). 키 교체는 8.2 비밀번호 변경과 같은 방식(`vercel env rm/add YOUTUBE_API_KEY` → `vercel --prod`). 키에는 「API 제한사항: YouTube Data API v3만」을 걸어 둘 것. 설교가 1시간 넘게 갱신되지 않으면 Vercel 로그에서 `[youtube]` 에러(키 만료·할당량 초과)를 확인.
7. Neon Postgres와 Vercel Blob은 Vercel Marketplace/Storage로 프로비저닝됨(`vercel integration list`로 확인). 별도 외부 계정 관리 불필요 — Vercel 대시보드의 Storage 탭에서 관리.
